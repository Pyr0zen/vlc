# INTERACTIONS: how the redesigned features affect each other

Read this before starting any work package and check it again before marking one done. Every new component must satisfy every rule below that touches it, even if the feature it depends on is built much later. When a new interaction is discovered, add it here.

## 0. Performance rules (Sticky, 2026-10-13; above every visual rule)
Responsiveness wins over visual effects every time; targets and measurements are in CLAUDE.md (Quality rules) and redesign/PERF.md.
- Background blur: only on panels, and only if it holds 60 fps; otherwise a solid or semi-transparent fill that looks close to it. (The video is a native surface under the QML scene and cannot be blurred at all; panels over the video use an opaque fill.)
- Seek thumbnails and waveform scanning: in the background at low priority; they never block playback or the UI.
- Seek preview card (W3.3b): one thumbnailer request at a time, throttled to one start per 150 ms, cancelled when the pointer leaves; nothing runs before the first hover. The card lives in the window overlay only while shown (above panels and the compact library). A later waveform / subtitle timeline seek bar mode (P6-06, P3-16) keeps the same scrubbing properties of SliderBar (scrubbing, dragging, scrubPosition) so the card works on every mode.
- Long lists always load rows lazily (ListView / GridView with delegates created on demand), never all at once (no Repeater over a model that can grow: queue, bookmarks, chapters, library).
- No polling and no timers running when nothing on screen needs them.
- Animations: the Figma durations where they exist, otherwise 150 to 200 ms at most; a click or key starts the visible response within one frame.

## 1. Live theme and accent (video 17:39-17:49, 19:49; Decisions 9, 15, 16, 20)
The user can switch Dark / Light / System and pick one of 9 accent colors at any time, from Settings > General and from onboarding, and everything recolors instantly.
- Never hardcode a color in QML or C++. Use `VLCStyle.palette.rd*` (design colors) or a `ColorContext` role. Hardcoded design colors are a bug.
- `palette.rd*` switch with the theme: dark values from the Figma "Dark" styles, light values from the "Light" styles (light FG/1 #111111, FG/2 #222222, Decision 33). VLC's ColorContext color sets use the same rd* roles in both themes (W8.4), so `theme.*` colors follow too. The player bars follow the theme over the video; only items drawn directly on the picture with no bar behind them keep `VLCStyle.darkPalette`.
- A theme or accent switch is instant (P8-41): color animations must go through `DelayedBehavior` (or be disabled while `VLCStyle.palette.switching`), never a plain `Behavior on color`. Choose light-only variants with `palette.isDark` only where the video's light theme differs from the token mapping (RdSegmented, RdButton Standard).
- Everything accent-colored must follow the live accent: play button, seek fill and playhead, toggles ON, selected tabs and underlines, checks, active icons, sliders, Save / primary buttons, focus borders, the cone app icon (video 17:46: the cone turns green / purple), the subtitle timeline buttons, waveform played bars.
- Icons: SVGs with colorizer slots only (`_res_C1` gray, `_res_C2` Accent/DIm, `_res_ACCENT` accent). No baked-in orange. Two-tone menu icons use Accent/DIm, which is derived from the accent too.
- Accent shades (Bright, DIm, BG/Accent Bright, BG/Accent Dark) are derived from the chosen accent; light theme has its own Accent set (Light/Accent/Main #E8851A) to derive from.
- Exceptions shown in the video: the volume cone keeps its green to red gradient in every accent and theme (17:44-17:49); the video area stays dark in light theme (17:43).
- VLC's Qt is built without Canvas, Shapes and Path (also no AnimatedImage, Flipable, Sprite, particles): custom drawing (cone, video frame, waveform, subtitle timeline) uses ShaderEffect shaders in modules/gui/qt/shaders or plain Rectangles/Images, bound to palette colors so it recolors live.

## 2. Bars, panels and video area
- Windowed: both bars show on mouse movement over the window and fade out about 3 s after it stops. Fullscreen: each bar shows per hover zone and fades out (Decisions 4 and 30). The cursor is tracked from mouse events only (no polling): a HoverHandler on the player, the video surface's moves and a HoverHandler on the surface (the surface accepts hover, so the player's handler does not see it) feed Player.qml's cursorTracker, which ignores hover events caused by window moves, resizes and fullscreen switches (the cursor did not move on the screen). Anything that opens from a bar (tracks popup, settings sidebar, queue sidebar, menus, tooltips, the editable time field, the resume toast) must keep the bars visible while open (lock) and release the lock when closed, including when closed by Escape, outside click, media change or window change.
- Only one player panel at a time (RdPanels): tracks popup, settings sidebar (Playback / Video / Audio / Subtitles), queue sidebar (Queue / Bookmarks / Chapters). Opening one closes the other; clicking the same button again closes it (F-06).
- Hide UI (Ctrl+\, right-click item) hides both bars and every panel; showing the UI again restores the bars but not panels.
- Info panels (W4.3b): Show Metadata and Show Statistics (Playback tab toggles, `RdPanels.metadataShown` / `statisticsShown`) sit at the top left of the video area, right of the compact library, under the sidebars (z 1) where a small window makes them meet. They are not RdPanels panels: they stay open beside any panel until their toggle or X switches them off, ignore outside clicks and Escape, do not lock the bars, hide with Hide UI and come back with the UI. Each panel and its data source (RdMediaMeta / RdInputStats) exist only while it is shown.
- Dismissal (UX pass 2026-10-15): a click outside the open panel closes it. Over the video it only closes the panel (no pause, no double-click fullscreen; right click opens the menu); on the bars the click still acts. Panels and their popups take clicks and the wheel on their empty parts. Escape order: drop-down list or menu, panel, Hide UI, then VLC. New overlays in the player must follow this; a new panel goes into RdPanels and the outside-press check in Player.qml.
- Fullscreen: same bars and zones; window buttons hidden; video frame (W3.7) not drawn; the fullscreen button in the top bar shows the exit icon.
- Side panels and the compact library dock inside the inset video area (IA-28, IA-43, P5-23); the video frame, panels, toast and seek thumbnail must not overlap each other badly at small window sizes.
- Pinned controls (VLC's existing option) keep working: bars always visible, video between them.
- Music view (P6-04): it is the picture area of audio media: drawn with the dark palette in every theme, framed like the video, the compact library floats over it without resizing it (the cover stays centred on the window), and its blurred artwork is drawn once per cover (no live blur): anything new drawn on it keeps VLCStyle.darkPalette and must not resize it per frame.
- In-window modal dialogs (Open Network Stream, W6.4) dim the whole window, bars included; the bars may fade underneath and come back on the next mouse move. Closing a dialog (Save, Cancel, X, Escape) gives the keyboard focus back to the item that had it.

- The Settings dialog is a modal panel over the whole window (hosted by MainInterface.qml, not by the player page): it does not lock the bars, so in a window they may fade while it is open; Escape closes the top-most popup first (dropdown list or info popover, then a non-empty search text, then the dialog).

## 3. Customize Player and profiles (video 19:12-19:36; W8.1, W8.2)
- Every control bar and top bar element must be a self-contained control that works wherever the user drags it (left, center, right, top bar, bottom bar), at any order, with any neighbours. No control may assume its position or look up siblings by position.
- The seek row (time, seek bar, duration) must work as a movable item (19:22 alternate layout moves it to its own row).
- The seek row never disappears from a video or audio bar: with an empty center zone it sits between the left and right controls; as soon as the center zone has controls it takes its own full-width row above them (two 54 px rows, Figma "Player - customize-1" / "-6" / "-7"). The live ControlBar and Customize Player's CustomizeBar follow the same rule, so the preview, Save and every profile (also VLC's styles with center controls) keep it.
- New controls (File / Folder / Playlist / Artist name, Favorite, Thumbnail, Bookmarks, Right Sidebar, Go Home ...) are added as `ControlListModel` types (append-only enum) with palette entries.
- Profiles switch layout and settings; any setting UI must reflect a profile switch live (bind to the source, never cache values).
- Step 1 (W8.1a): dialogs/toolbar/qml/CustomizePlayerDialog.qml edits VLC's zones (left / center / right per player layout) in its own bar drawn over the live control bar (CustomizeBar / CustomizeZone, dashed outlines via Widgets.RdDashedFrame); the live bars follow the edited models behind it. W8.1b moves the editing onto the real top and control bars (top bar model, movable seek row and title) and adds the Figma-only controls to CustomizePalette (icon, name, outline size per control); keep the palette's 50 ms shifts and the cursor hot spot. Its profile dropdown and "..." menu make way for the main menu Profile entry with W8.2.
- W8.1b / W8.2 (redesign/CUSTOMIZE_NOTES.md): the top bar is the profile's top bar layout (RdProfiles.topBarModel, identifier 3 of VLC's profile record), drawn by RdTopBarZone and edited by CustomizeTopBar; its right zone sits between the window's maximize and close buttons. The new controls use the redesign's own id range (0x80 on). A control that opens a popup emits `requestLockUnlockAutoHide` like the bar's other controls, and must not watch data while `paintOnly` (Customize sets `paintOnly` after the control is made). Profiles live in the main menu (RdMenuModel "Profile (name)"); a switch applies the layouts at once and the settings from a worker thread (RdProfiles, RdProfileSettings), then `RdProfiles.applied` refreshes RdEffects and RdProfileNotice says what applies later. Any new cache of settings in the interface must be re-read on `applied`.

## 4. One source of truth for settings
The same option can be changed in several places: the right sidebar tabs, the Settings dialog pages, menus, hotkeys, per-show presets and profiles.
- All of them read and write the same VLC option / player property and update live when it changes elsewhere (e.g. subtitle delay from the sidebar slider, from G/H hotkeys, from a preset).
- Presets (Decision 18) apply to every tab at once; the sidebar must show the active preset's values right after it is applied.
- Endless sliders (Decision 47, RdEndlessSlider): a value set from elsewhere (preset, hotkey, profile, typed) that lies past the slider's normal range scrolls its scale to show it; once it is back in the normal range the normal view returns. Never clamp such a value to the slider's normal range in a setter.
- Mouse wheel (Decision 54): an RdSlider takes the wheel over its bar and label row (RdSliderWheel: one step per notch, through the slider's normal moved / valueMoved path); a wheel gesture already scrolling a list passes through. Every overlay over the player or a list takes the wheel nothing inside it used: RdPanel, popups (Qt's Popup eats it over itself; modal ones everywhere), RdCascadeMenu and RdMenuPanel (also outside while open), and an RdWheelSink filling other cards under their content (mini player card and picture, the compact library's host in Player.qml, resume toast). The bars take it too, their empty parts included: TopBar (an RdWheelSink under its controls), ControlBar (`wheelEnabled`), the minimal view's window buttons; in the player only the video area (the music view's picture area in its place) and the volume control (VolumeWidget: speaker and cone) react to the wheel, the seek bar and the other bar controls take none. A new overlay must do the same, a new bar control must not use the wheel unless it is the volume, and a new slider must be an RdSlider (or use RdSliderWheel) so the wheel fine-tunes it.
- Options that only apply on the next file or vout must say so (Decision 29 notice) instead of silently doing nothing.
- The Settings dialog pages (W6.1/W6.2) read and write options through RdEffects like the sidebar, so a value changed in one shows in the other right away; a page binds to `RdEffects.revision`, never caches a value.
- VLC's complete preferences ("All VLC Settings") write the same options; the redesigned dialog closes before they open, and reopening it re-reads every value.

## 5. Seek bar modes
The seek bar has several looks that can combine: thick bar (default), chapter segments (IB-46), subtitle timeline (P3-16, zoomed window with asterisk times), waveform (P6-06, music and the "Show Waveform" option), hover thumbnail (Decision 6), bookmarks marks. Build the seek bar so these are layers / modes of one component, not separate copies.
- Waveform (P6-06, redesign/WAVEFORM_NOTES.md): a layer of SliderBar's background (RdWaveformItem over the trough, the plain fill fading out under it), shown while the option `qt-seek-waveform` is on and the playing file's scan is ready (RdWaveform singleton). It never takes input: hover, drag, the preview card and keys stay SliderBar's (the seek bar takes no wheel, Decision 54). It reads the playhead's center and width from the handle, so a later mode that moves or resizes the playhead keeps the bars cut around it. Only one waveform scan runs at a time, at the lowest thread priority, and only while a thick seek bar shows the option.

## 6. Library and playback
- The folder chip and sidebar toggle open the compact library over the video (W5.1); the full library, mini player and queue card share the same models and selection.
- Drag and drop from the library or the file manager into the queue must work over the video, the panels and the mini player.
- Watched state / progress (thumbnails, Unwatched First sort, resume toast time) all come from the media library progress.

## 7. Keyboard, focus, accessibility, translation
- Every new interactive element: keyboard reachable, visible focus, `Accessible.name`, `qsTr` / `qtr` text. Escape closes the top-most popup first.
- Hotkeys keep VLC defaults (Decision 22); new shortcuts: Ctrl+\ Hide UI, Ctrl+B bookmark. OSD shows the pressed key (W7.3).
- Ctrl+B (W4.8b) lives in MLGlobalShortcuts.qml (media library only, like VLC's bookmarks): it adds a bookmark through MLBookmarkModel.add(), the same call as the Bookmarks tab "+" and the Custom Bookmarks menus' "Create"; every MLBookmarkModel (sidebar list, menus, VLC's editor) refreshes from the media library event. A file played for the first time is added to the media library first (as the player does when it stops). The confirmation "Bookmark added: <name>" is the interface's notification (MediaLib::bookmarkAdded -> UINotifier -> FloatingNotification above the control bar, in the player, the library and the minimal view), not VLC's on-screen message, whose top right corner of the video window lies under the opaque top bar and the open sidebar. When W7.3 restyles the on-screen messages, this notification follows the same style.
- Sleep Timer (W4.3b, RdSleepTimer): "End of current file" borrows the play queue's media stop action (VLC's play-and-stop) and gives it back; "Quit at the end of the play queue" or another change of that action ends the timer instead. A minute countdown ends with VLC's Stop.
- Hotkey names shown anywhere (menus, onboarding 19:50, OSD "Pressed C", Keyboard Shortcuts dialog) use the same formatting: HotkeysModel.displayKeys() ("Ctrl + F"). Hotkeys edited in the dialog apply after a restart until the core key map can be reloaded (W6.3).

## 8. Sizes and scaling
- All sizes go through `VLCStyle.rd_*` / `VLCStyle.dp()` so Windows scaling 100 / 125 / 150 % and VLC's own interface scale work. Test at small window sizes: panels, toast and title must elide or shrink, never overlap the window buttons.

## 9. Fonts and text
- Inter everywhere (`VLCStyle.rd_fontFamily`), bundled with the app. Long file names elide.

## 10. Menus (W4.9, W4.10)
- The main "..." menu and the right-click menu are QML (`menus/qml/RdCascadeMenu.qml`) drawing VLC's own QMenus through `RdMenuModel` (`menus/rd_menu_model.cpp`). New entries go into the C++ builders so they keep VLC's actions; entries that need QML (Hide UI, Show Queue, Keyboard Shortcuts, Customize Player) are emitted as `requested(id)` and handled in `RdMainMenu.qml` / `RdPlayerMenu.qml`.
- Later packages hook in there: W6.3 points "keyboardShortcuts" at its dialog, W8.1 points "customizePlayer" at the Customize Player screen, W8.2 adds the "Profile (name)" submenu after the divider below Open Recent, W6.1 changes what Settings (prefsDialog) opens. The library top bar (Phase 5) should use `Menus.RdMainMenu` too.
- An open menu keeps the bars visible (lock) and releases them when it closes. While the player is shown, `DialogsProvider.rdPopupMenu` routes VLC's right-click and Menu key requests to the QML menu.
- Hide UI state lives in `RdPanels.uiHidden`; any new bar or panel must hide with it.
